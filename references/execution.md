# Sustained execution and progress

1. Inspect project status, actual saved reports and active execution before resuming. Keep one CAD writer per project; a monitoring job must not edit CAD. Preserve correct work and complete useful independent work while a genuine external blocker waits.
2. When recurring updates are requested, inspect the existing scheduler first and merge its settings through supported tools. Record the destination, interval and project. Send cross-channel updates only to the authorized verified destination; report unavailable delivery rather than guessing a recipient. Do not create duplicate execution jobs.
3. Distinguish scheduler acceptance/queued, observed running, saved milestone, validated artifact and delivered result. A queued message or running flag is not proof of design progress; a delivery error invalidates an earlier admission acknowledgment. Report actual saved changes, remaining work and evidence-based ETA. If a forecast slips, explain why and revise it; do not reset the same estimate each run.
4. Batch related component checks and finish coherent circuit/layout blocks. Reuse verified local datasheets. After repeated identical download or routing failure, change method: inspect exact error, source/version, placement, topology and stackup. Do not keep nudging coordinates or maximizing a ground-coverage percentage as a substitute for electrical acceptance.
5. For USB/RF/power layout, inspect manufacturer reference designs and exact reference-CAD revisions. Evaluate impedance against the selected actual stackup, return continuity, transitions, stubs, critical loops and mechanical constraints. Reference boards provide evidence, not permission to copy unexplained omissions. Distinguish analytical estimates from bench qualification.
6. Classify remaining work as locally fixable defect, supplier decision, user decision, or physical prototype test. Fix local defects; obtain only necessary decisions; provide a concrete bring-up plan for physical tests. Do not claim hardware performance from CAD, and do not cycle indefinitely attempting to prove hardware-only behavior in software.
7. Before pausing/completing, checkpoint exact artifacts, results and next action; disable the task's recurring job when it no longer has actionable work. Explain the stop and external dependency. Report local delivery completion separately from supplier approval and functional readiness.
