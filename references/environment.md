# Environment and defaults

The skill is a conversational AgentSkill, not a shell executable. Discovery uses name/description and native skill invocation. Do not add gateway routing keys or regular-expression dispatch hooks. Native slash invocation may also be offered by OpenClaw; use the identity actually returned by discovery.

Defaults are ordinary skill-owned JSON, not OpenClaw configuration keys. Initialize ~/pcb-projects/pcb-defaults.json once from assets/defaults.json using exclusive creation; keep it human-editable. Read before editing and make a backup for persistent-default changes requested by the user. A current-task override must change only project requirements/effective settings. Merge task > project > user defaults > fallback recursively. Explain invalid JSON rather than discarding user settings. If assembly is disabled, omit BOM/CPL assembly work as inapplicable and still report the three Economic rows as not applicable; do not change global defaults.

Inspect installed OpenClaw version/native docs and local examples when installing/updating, not on every design turn. Discover actually callable tools; tool availability and permission are runtime facts. No dependency gating in skill metadata should hide this self-bootstrapping skill when KiCad is absent.

Stages: interview needs workspace/config and research as required, not a running desktop. Reprice needs project BOM/requirements and official catalog/quote information, not CAD GUI. Package/modify/resume/design need appropriate KiCad operations. Check kicad-cli version/help, Python/Git and needed exporters; probe pcbnew with the Python interpreter that owns it (Ubuntu package uses /usr/bin/python3). No particular minor version is required if the installed supported stable version works. Check a GUI/computer node only when needed; do not reinstall or downgrade working software.

Use shell for Linux administration. Verify official KiCad OS-specific stable repository instructions if installation is needed; avoid nightly. Inspect sudo -n availability rather than assuming. Before consequential changes inspect existing package/repository configuration and active editor state, preserve unsaved work, archive and verify complete project, explain unavoidable compatibility. Ask only for actual missing authority/interactive credential entry. Never collect credentials in chat, expose services publicly, change authentication/model routing without need, disable security, rerun onboarding, or install unverified scripts.

Use a supported KiCad API/native template before custom file generation. Check existing maintained solutions before creating additional custom infrastructure. GUI editing is permitted, not mandatory; programmatic CAD must be verifiable and safely reloaded. No brittle blind textual rewrites.

One owner controls the CAD desktop. On COMPUTER_HOST_BUSY stop repeated retries, identify the active owner with available session/node tools, distinguish active from stale execution, use documented recovery and preserve work. No parallel screenshot commands against the same desktop, duplicate node processes, force-killing unrelated tasks, closing unsaved KiCad or restarting VNC. Routine GUI actions should be economical; more reasoning belongs on electrical decisions. Do not invent model identifiers or suggest tool selection changes billing.

Existing templates must load, have valid intended layers/stackup/rules and contain no circuit components, named nets, tracks or old outline unless explicitly general/mechanical. Check old permission text in context: this workflow authorizes local manufacturing generation; upload/order authorization is separate. Preserve user standards; document a specific project-level interpretation/override instead of removing electrical safeguards. An old guard demanding supplier review is an order-release gate, not a reason to withhold local candidate files.

## Clean-install bootstrap
When standards or the ordinary-board template are absent, create the workspace and needed general standards from effective defaults and current authoritative manufacturing requirements. Record sources and dates; distinguish preferred geometry from supplier limits. Create an empty template using the installed supported KiCad API or native editor, with no demonstration symbols, footprints, named circuit nets or routing. Reopen it and verify layers, stackup, rules and library references. An absent outline is intentional until project mechanical requirements are known; do not claim that an outline-free template passes finished-board DRC. Preserve existing user standards and templates. If creation cannot be verified, record the exact blocker rather than assuming this distribution contains a template. Do not create a real board during installation validation.
